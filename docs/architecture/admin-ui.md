# 운영관리 프론트

P1-03의 비AI 운영 기능을 일반 사용자 화면과 분리한 `admin` 경로에 둔다. 내 공간은 일반 인증의 `GET /v2/admin/eligibility`가 명시한 역할을 확인한 뒤에만 진입 버튼을 표시한다. 권한 조회 실패나 역할 없음은 운영 진입을 표시하지 않는다. 역할 부여는 이 UI에서 제공하지 않는다.

## 인증과 상태 경계

- 운영 화면의 **운영 세션 시작**을 눌러야 일반 인증으로 `POST /v2/admin/sessions`를 요청한다. 응답의 `owner_id`와 현재 연결 계정이 일치해야 한다.
- `AdminSession`은 운영 bearer를 JavaScript private 필드에만 보관한다. React snapshot은 역할, owner, 만료 시각, 세대 번호만 제공한다. URL, AsyncStorage, localStorage, 세션 저장소, 작업 영수증에는 운영 bearer나 변경 요청을 저장하지 않는다.
- 운영 API는 `authenticated=false`인 HTTP 요청에 운영 bearer를 직접 설정한다. 일반 인증 토큰으로 운영 자료를 요청하지 않는다. 401/403, 화면 종료, 앱 백그라운드, 만료, 계정 전환은 메모리 세션을 닫는다. 명시 종료와 화면/백그라운드 종료는 서버 폐기도 요청하며, 폐기 연결 실패에도 로컬 세션은 즉시 비운다.
- 세대 번호와 owner를 검사하여 닫힌 세션의 늦은 발급/조회/변경 결과를 버린다. 목록 필터/재조회가 바뀌었을 때 이전 페이지 응답도 현재 목록에 합치지 않는다. 계정 저장소는 사용하지 않으므로 계정 연결별 저장소 구현과 독립적이다.

## 역할과 명시 변경

`viewer`는 카탈로그, 출처/라이선스, 게시 이력, 의견 목록, 감사 기록, OTA 정책만 조회한다. `publisher`는 서버가 확인한 게시 역할로 다음 변경을 실행할 수 있다. 서버의 역할 검사는 최종 권한 경계다.

| 기능 | 계약과 확인 내용 |
| --- | --- |
| 권리 검토 | 검토 메모 1~1000자, 승인/반려, `expected_review_version`. 현재 게시된 버전의 반려는 게시 중단도 확인한다. 승인으로 자동 게시하지 않는다. |
| 게시 | 덱 이름/버전, 현재 게시 ID, 출처 수, 검토/게시 버전을 확인한 뒤 `/catalog/{version_id}/publish`. 승인 전에는 버튼을 활성화하지 않는다. |
| 롤백 | 해당 버전의 실제 이전 게시 ID를 사용자가 선택한다. 현재 ID/선택한 ID/게시 버전을 확인하고 `/rollback`을 보낸다. 원본 에셋/버전을 재작성하지 않는다. |
| 의견 분류 | 상태별 필터와 cursor 목록, 상태 변경 전 현재 상태/선택한 상태/`expected_version` 확인. |
| 감사 | cursor 목록과 서버가 공개한 변경 메타데이터. `audit_retention_days`가 null이면 **정책 미정**, 숫자이면 받은 일수를 표시한다. 보관 기간을 클라이언트가 정하지 않는다. |
| OTA | 채널/최소 네이티브 버전/허용 상태/정책 버전 조회. 중단·재개만 명시 변경하며 채널과 최소 버전은 받은 값을 그대로 보낸다. `expected_version` 충돌 시 실패로 표시한다. 앱/번들 파일 배포 기능은 아니다. |

모든 변경은 별도 확인 요약 뒤 적용한다. 버전 충돌 또는 통신 실패가 나면 성공으로 처리하지 않고 후속 변경을 잠근다. **최신 정보 다시 조회**로 서버 상태를 확인한 뒤 새로 선택해야 한다. 변경 요청은 저장하지 않으며 무인 자동 재전송하지 않는다. 모델 프롬프트 및 AI 사용량 관리는 이 범위에서 제외한다.

## 검증

새 단위 테스트 5개는 메모리 전용 토큰, 만료/owner 전환, 늦은 발급과 결과, 명시 역할, 별도 Authorization, CAS, 권한 거절을 검증한다. 새 브라우저 테스트 2개는 일반 사용자 진입 숨김, viewer 조회와 저장소 토큰 부재/백그라운드 종료, publisher 검토·게시·지정 롤백·분류·OTA 중단/재개·409 재조회·403 세션 폐기를 fixture로 확인한다. 실제 운영 역할 부여, 실제 후보 덱 게시 및 실제 OTA 배포는 수행하지 않는다.
