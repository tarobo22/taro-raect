## 계약과 아키텍처

React 화면 → hook / 기능 유스케이스 → repository port → API adapter → FetchClient. FastAPI router → application → domain / repository·UoW ports → PostgreSQL / 제공자 adapter. 화면에 fetch나 SQL을 섞지 않는다. 기능별 도메인 규칙·소유권·동시성은 서버에서 확인한다.

원본 API 50개의 경로·메서드·성공 상태가 현재 OpenAPI와 모두 대응한다. 이는 모든 원본 JSON Schema가 문자 단위로 같다는 뜻은 아니다. 기존 P0 operationId 28개 차이는 API 추적표에서 연결했다. 초안 API명이나 테이블명이 그대로 구현됐다고 표시하지 않는다.

AI 요약 계약에는 선택 경쟁을 막기 위한 선택적 entry_versions 입력과, 원본 열기에 필요한 entry_ids·entry_versions 출력이 추가됐다. 신규 화면은 선택 버전을 전송한다. 실제 계약은 docs/contracts/openapi.json을 따른다. 원문은 작업·멱등키 저장소에 복제하지 않으며, worker가 목적별 동의·소유권·버전을 재검증한 뒤 호출한다. 외부 I/O 동안 DB 트랜잭션을 유지하지 않는다.

원본 일일 AI 한도 30회와 현재 정책의 사용자 20회/전체 200회·UTC일 차이는 기존 정책을 유지한 차이다. 조회·집계는 AI를 자동 호출하지 않는다. 명확한 감정 점수 확정 출력은 insight에 한정해 추가 차단하며, 자연어 전체를 완벽하게 판정한다고 주장하지 않는다.

현재 실DB 31개 테이블(마이그레이션 이력 포함)·229개 컬럼·75개 PK/UNIQUE/FK 메타데이터에서 ERD를 생성했다. 요약의 원본 ID/version은 원본 삭제 후 무효화 검증을 위해 FK 없이 최소 참조만 보존하며, 소유자 전체 삭제 시 함께 삭제한다. 물리 ERD는 FK 관계만 그리므로 이 최소 참조를 강제 FK로 오해하지 않는다.
