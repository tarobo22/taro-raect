# TDD·테스트·Git 평가와 재구성 기록

## 원래 작업 평가

| 항목 | 평가 | 근거 |
|---|---|---|
| 매 기능 RED → GREEN | 부분 준수 | 마음기록·규칙·재시도에서 RED를 확인했지만, 일부 통합 검사·AI 경계 검사는 구현 후 추가했다. |
| 기능별 커밋 | 부분 준수 | 도메인·유스케이스 커밋은 분리했지만, 서버 저장·HTTP·AI가 묶인 커밋과 미커밋 화면 변경이 남았다. |
| 기능별 push | 미준수 | 당시 인증은 gaya573이었고 tarobo22 저장소 접근이 404라 성공한 push가 없었다. |
| 테스트의 가치 | 핵심 경계에는 의미 있음 | 실제 PostgreSQL rollback·소유권, 중복 저장·재시도, DTO 오류, AI 실패 처리를 확인한다. |
| UI·출시 검증 | 부족 | 테스트 통과만으로 입력 보존·제스처·음성·햅틱·운영 OTA·상담 품질을 보장하지 않는다. |

## 이번 재구성의 의미

사용자 승인에 따라 기존 소스·이력·미커밋 변경을 먼저 ZIP·Git bundle·patch로 보존했다.
원격이 비어 있음을 확인한 뒤 새 main을 초기화하고, 기능 단위 검증 → commit → push → 원격 SHA 대조를 반복했다.
기존 구현을 재구성한 이력이다. 원래 개발이 전부 TDD였던 것으로 소급해서 표시하지 않는다.

도메인·트랜잭션·HTTP·재시도 경계는 미구현 또는 동작이 빠진 작업본에서 기존 테스트가 실패하는 RED를 확인하고,
보존한 구현을 복원한 GREEN을 확인했다. 이는 테스트가 해당 동작의 결손을 잡는다는 증거다.
화면 복원 커밋의 주된 자동 검증은 TypeScript 검사다. 화면 전부가 자동 UI TDD로 검증됐다는 뜻은 아니다.

## 가치가 큰 테스트

- 명시 commit 없이 나간 트랜잭션이 실제 PostgreSQL에 남지 않는지 확인한다.
- 타 소유자가 기록을 읽거나 바꾸거나 지우지 못하는지 실제 SQL 경계에서 확인한다.
- 연속 저장이 한 번만 호출되고, 불확실한 네트워크 재시도는 같은 요청 ID를 쓰는지 확인한다.
- 같은 요청 ID에 다른 내용을 보내면 충돌 처리하고, 일일 카드가 고정되는지 확인한다.
- 잘못된 API 응답·실패 HTTP 응답이 저장 성공으로 처리되지 않는지 확인한다.
- AI 동의가 없으면 거절하고, provider 오류·미완료 응답을 성공으로 표시하지 않는지 확인한다.

## 과장하면 안 되는 테스트와 남은 공백

- `a failed save preserves input...`는 입력 객체 불변성과 재시도를 검사한다. 실제 화면 글 보존·이동 여부까지 검사하지 않는다.
- `an invalid persistence acknowledgement...`는 DTO 거절을 검사한다. 화면 폼 상태를 직접 검사하지 않는다.
- 일부 필드 보존·mock 호출 검사는 실제 DB/HTTP 검사와 겹쳐 단독 가치가 낮다. 허가 없이 기존 테스트를 삭제·완화하지 않았다.
- 타로 재시도 검사는 순차 재요청이다. 실제 동시 요청·AI 과금 경쟁 조건 검사는 별도로 필요하다.
- 소유권 HTTP 검사는 소유자 의존성을 주입한다. 실제 세션 생성·401·만료·복구 흐름 전체를 대체하지 않는다.
- GPT 검사는 MockTransport 계약 검사다. 실제 키·모델 호출 및 답변 품질 평가는 아직 수행하지 않았다.
- 새 화면의 제스처·접근성·실패 후 글 유지와 네이티브 오디오 생명주기·실기기 햅틱은 추가 검증 대상이다.

## 숫자 해석

백엔드는 30개 case, 클라이언트 공통은 11개 case다. 공통 11개를 RN·웹에서 각각 실행하며 서로 다른 기능 22개로 세지 않는다.
검사 개수와 코드 커버리지 비율을 혼동하지 않는다. 이번에는 커버리지 퍼센트를 측정하지 않았다.

## 재구성 중 발생한 문제

- 초기 OpenAPI 구성에 남은 router 참조: 게시 전 검출, 사용자 승인 후 수정·재검증했다.
- 카드 원본 목록 79개를 모두 앞면으로 센 조건: 앞면 78개와 참고 뒷면 1개를 구분해 사용자 승인 후 수정했다.
- 외부 CC0 원문의 첫 줄 탭: 원문 바이트를 보존하고 그 외부 원문 한 파일만 코드 공백 검사에서 제외했다. 제품 테스트는 제외하지 않았다.

실제 RED/GREEN 출력과 커밋·원격 SHA 기록은 로컬 백업 폴더의 verification 및 rebuild-events.json에 보관했다.
